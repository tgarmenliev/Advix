# Фаза 4 — Съдлъжници, имоти и финанси

## Цел

Да завърши досието около заявката: свързаните лица (съдлъжници), имотите за
ипотека и финансовите изчисления, които консултантът гледа при преценка.

## Какво включва

- **Свързани лица** (`FamilyMember`): съпруг/а, съжител, съдлъжник.
- **Имоти** (`Property`) за ипотека.
- **Финансов калкулационен слой** — само изчислява и показва.

### Endpoints

| Метод | Път | Описание |
|---|---|---|
| POST/GET | `/clients/:clientId/family-members` | Добавя / изброява свързани лица |
| GET/PATCH/DELETE | `/family-members/:id` | Един / редакция / меко изтриване |
| POST/GET/PATCH/DELETE | `/properties`, `/properties/:id` | CRUD за имоти |
| POST/GET/DELETE | `/loan-applications/:id/family-members` | Включва/изброява/маха лице в заявка |
| POST/GET/DELETE | `/loan-applications/:id/properties` | Свързва/изброява/маха имот |
| GET | `/loan-applications/:id/financial-summary` | Финансово резюме |

## Ключови решения (и защо)

### Съдлъжникът има същите полета като клиента
За всяко свързано лице се отварят абсолютно същите данни като на основния клиент,
и се ползва **същата ЕГН валидация и изчисляване на възраст** (споделен код).
Всяко лице има и **собствено GDPR съгласие** — правно е отделно лице.

### Пари винаги като цели числа (стотинки)
Всички суми са `int` в стотинки (напр. `150000` = 1500.00 лв). Пазим **стотинки**,
а не левове, защото стотинката е най-дребната единица и винаги е цяло число —
така избягваме грешките при закръгляне на числата с плаваща запетая (`0.1 + 0.2`
не дава точно `0.3`). Десетичната запетая се слага само при показване.

### Финансовият слой само изчислява — не решава
`FinancialCalculationService` е чист калкулационен слой без странични ефекти. Той
**не** взема кредитни решения, **не** препоръчва суми и **не** блокира workflow —
показва числата, консултантът преценява (изрична забрана от заданието).

Изчислява:
- **Общ доход** = доход на клиента + доходите на лицата, **включени в тази
  заявка** (не всички роднини!).
- **Общи задължения** = месечните вноски, които няма да се рефинансират.
- **Дълг/доход** = задължения / доход (при нулев доход → `null`, не грешка).
- **Самоучастие** (само при ипотека с покупка) = пазарна цена − размер на кредита.

### Имот ↔ заявка: данните на връзката са отделни
Пазарната цена (`marketValue`) и банката на ипотеката се пазят в **junction
записа**, не в самия имот — един имот може да участва в различни заявки с различен
контекст.

## Правила и валидации

- Дедупликация на съдлъжник: същото ЕГН два пъти към същия клиент → `409`.
- Не може да включиш в заявка лице от **друг** клиент → `400`.
- Имот, свързан към `CONSUMER` заявка → **warning** (не блокира).
- Изтриване на имот, свързан към заявка → **блокира** (`409`) — първо се маха връзката.

## Тестове

- ЕГН валидация и възраст за съдлъжник (споделената логика).
- **Доходът брои само включените лица** (клиент 200000 + включен 150000 = 350000,
  а не 450000 с невключения) — специфичен тест за коректност.
- Дълг/доход при нулев доход → `null`.
- Самоучастие при ипотека с покупка → правилна стойност; без имот → `null`.
- Политика при изтриване на свързан имот.

## Как да се провери

```bash
# Финансово резюме на заявка
curl http://localhost:3000/loan-applications/<APP_ID>/financial-summary \
  -H "Authorization: Bearer <T>"
# → { totalIncome, totalObligations, debtToIncomeRatio, downPayment, ... }
```
